# P0 配额、订阅与财务验收

本清单覆盖当前 P0 范围：Agent 断流、配额分组管理、订阅状态机和本地财务模型。

## 共同规则

- 自动测试只能使用本地测试存储、CI PostgreSQL 服务或明确指定的可丢弃数据库；不得连接 UAT/PROD。
- 手工验收仅在 UAT 使用专用测试用户、测试订阅和测试付款 Provider 对象。
- 不得删除用户、UUID、订阅、付款、退款、用量账本或审计事件；失败回滚采用前向修复。
- 每项通过时记录 PR、合并 SHA、不可变 UAT tag、迁移版本（如有）及验收人员和时间。
- 在前一项获得 UAT 人工通过前，不合并、发布或验收下一项。

## P0-A｜Agent 超额断流与恢复

### 自动回归

脚本位于 Agent 仓库：

```bash
./scripts/test-p0-agent-quota-disconnect.sh
P0_RACE=1 ./scripts/test-p0-agent-quota-disconnect.sh
```

覆盖的核心断言：

| 用例 | 期望结果 |
| --- | --- |
| 配置事件到达 | 配额或同步资格变化立即触发处理。 |
| 事件丢失 | 最长 30 秒兜底对账。 |
| 重复事件 | 相同 revision 不重复执行。 |
| 额度耗尽 | 移除目标 UUID；对同一 Xray target 合并为一次重启。 |
| 已建立连接 | `RemoveUser` 后经所需 Xray 重启被断开。 |
| 额度恢复 | 热添加用户，不重启 Caddy。 |
| 重启失败 | 保留待重试状态。 |

### UAT 手工验收

1. 准备两个 Free 测试用户 A、B；A 建立 VLESS 持续下载连接，B 建立独立连接。
2. 将 A 本期用量精确调整至 5 GiB 或以上，保留用户、UUID、历史用量和订阅记录。
3. 验证 A 的存量连接断开，且 A 的订阅配置不再被 Agent 同步。
4. 验证 B 不会被删除；若与 A 共用 Xray target，可接受一次短暂重连，但必须恢复。
5. 将 A 额度恢复到有余额，验证无需 Caddy 重启即可重新获取配置并连接。
6. 检查 Agent 日志/指标：事件处理、目标重启次数、恢复热添加和失败重试均可追踪。

通过条件：A 被断流且可恢复；所有记录仍存在；Caddy 入口持续可用。

## P0-Q｜配额分组管理

依赖：P0-A 已在 UAT 人工通过。

### 自动回归

Accounts 脚本：

```bash
./scripts/test-p0-quota-group-management.sh
```

Portal 必跑 P0-Q 的管理组件和 BFF 路由测试：

```bash
./scripts/test-p0-quota-group-management.sh
```

该脚本使用仓库的 jsdom Vitest 配置，仅选择本 P0 引入的预览、批量确认和仅有效期变更用例。全量管理组件套件中仍有与本特性无关的既有展示断言失配，需另立修复任务，不能用来阻塞本 P0 的验收。

覆盖的核心断言：

| 用例 | 期望结果 |
| --- | --- |
| 管理员权限 | 非管理员及无 `admin.settings.write` 权限请求被拒绝。 |
| 预览 | 理由必填，预览 token 为一次性且 10 分钟过期。 |
| 单用户 | Free 5 GiB、Plus 20 GiB、Unlimited Beta 都可预览后应用。 |
| 批量 | 最多 500 人、原子应用；中间对象状态变更时整批拒绝。 |
| 幂等 | 同一请求重放不重复变更或重复写审计。 |
| 用量 | 切换套餐不重置本期已用字节。 |
| 超额 | 降到 Free 后已超额者剩余为 0，配置同步将暂停。 |

### UAT 手工验收

1. 使用管理员进入既有用户管理界面，确认布局与原有普通分组编辑能力保持一致。
2. 对单用户分别预览并应用 Free、Plus、Unlimited Beta；每次填写理由。
3. 核对预览显示的已用流量、剩余流量及“配置同步将暂停”影响。
4. 选择 2–5 个专用用户做批量变更；重复提交相同确认请求。
5. 用无权限账户尝试访问同一 BFF 路由，确认得到 403。
6. 将已使用超过 5 GiB 的测试用户降到 Free，确认其进入 P0-A 的暂停/断流路径。
7. 核对管理员审计记录：操作者、理由、请求 ID、用户范围、前后状态均完整。

通过条件：预览、确认、审计和批量原子性完整；既有用户未被默认改组；超额行为与 P0-A 一致。

## P0-S｜订阅状态机与自动降级

依赖：P0-A、P0-Q 已在 UAT 人工通过。

### 自动回归

```bash
./scripts/test-p0-subscription-state-machine.sh
```

覆盖的核心断言：

| 用例 | 期望结果 |
| --- | --- |
| Active / trialing | 有效 Stripe 订阅保持付费权益。 |
| Scheduled cancellation | 至当前周期结束才降至 Free。 |
| Manual validity | 到期日次日 UTC 00:00 降级，无隐式宽限。 |
| Past due | 仅明确的 14 天付款宽限内保留权益。 |
| 缺少账期 | 最多重试 24 小时，之后转 Free。 |
| 全额退款 | 仅明确成功的全额退款撤销权益。 |
| 升降级 | 升级只补套餐差额；降级保留当期用量。 |
| Sweep | 后台每轮有界分页，不依赖客户端或 Agent 请求。 |
| Agent 响应 | 协调后再次读取拦截状态，同一响应立即生效。 |

### UAT 手工验收

1. 为测试用户建立 Plus 订阅，确认其获得 20 GiB 权益。
2. 设置周期末取消；周期结束前仍可用，结束后自动转 Free。
3. 把本期已使用 19 GiB 的 Plus 用户降级到 Free，确认剩余为 0，而不是重新获得 5 GiB。
4. 恢复 Plus，确认剩余应为约 1 GiB，不重复发放整月额度。
5. 设置手动有效期和 `past_due` 场景，分别核对 UTC 到期和 14 天明确宽限。
6. 触发/等待后台 sweep，检查无访问量账户也被协调；检查 Agent 返回的授权立即反映结果。

通过条件：权益只由有效订阅或手动有效期决定；转换幂等；不会删除或重写历史财务与用量事实。

## P0-F｜本地财务模型

依赖：P0-S 已在 UAT 人工通过。

### 自动回归

```bash
./scripts/test-p0-local-finance-ledger.sh

# 仅用于明确指定的可丢弃 PostgreSQL 数据库；不得传入 UAT/PROD URL。
P0_POSTGRES_URL='postgres://...' ./scripts/test-p0-local-finance-ledger.sh
```

CI 必须在 PostgreSQL 17 的新数据库连续执行
`sql/migrations/tests/local_finance_ledger_upgrade_test.sql`，包含两次迁移执行。

覆盖的核心断言：

| 用例 | 期望结果 |
| --- | --- |
| 平滑迁移 | `2026092801` 仅追加结构，可重复执行，旧订阅/用量不变。 |
| RLS | 财务表启用 RLS，`anon` 与 `authenticated` 无任何表权限。 |
| 发票与付款 | 一张账单仅允许一笔全额已结付款。 |
| 幂等 | 相同 key 返回原事实；不同 key 的重复付款被拒绝。 |
| 退款 | 累计退款不能超过付款额；Provider 操作保留审计。 |
| 不可变性 | 发票、付款、退款和操作事件不可更新或删除。 |

### UAT 手工验收

1. 通过受控 UAT 增量迁移器只应用 `2026092801_local_finance_ledger.up.sql`，记录前后 schema version。
2. 比对迁移前后既有 `subscriptions` 与用量账本行数、关键字段及抽样内容，必须无变化。
3. 创建专用测试发票、付款、部分退款和 Provider operation；核对本地 UUID 是业务主键，`stripe_*`/provider ID 仅为外部引用。
4. 重放同一付款/退款请求；再以不同幂等键尝试重复付款，确认后者拒绝。
5. 使用 anon/authenticated 角色验证无法读取或写入 `finance_*` 表。
6. 尝试更新或删除财务事实，确认数据库拒绝且审计事件保留。

通过条件：迁移可原地、可重复、无旧数据破坏；财务事实仅由服务端访问且不可篡改。
